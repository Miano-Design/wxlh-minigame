## 四、结算页那件事的取证（因为它是"改了好几轮都没好"的那个）

前几轮一直在加保险（记住上一张面板 / 把这一场钉进闭包 / 三块装饰各包一层 try），
越修越不对。这一轮换了个问法立尺子：**同一场战斗结算两次，会发生什么？**

`scripts/settle_audit.js` 第一次运行就抓到了真元凶：

```text
settleRun() 里那句 `if (win && isWorldBoss && Story.markBoss)`，
而 win 是 onEnd 的参数、在 settleRun 这个函数里根本不存在
  ⇒ 每场结算都停在 `run = null` 之后抛 ReferenceError
  ⇒ 被 catch 兜住、返回兜底面板
  ⇒ 奖励已经发了，玩家看到的是「结算数据不在了 · 先回世界」。
```

它不是间歇性的：R3.16（`f6dfcc0`）之后，**每个玩家的每一场结算都在抛**。

真机（模拟器）实测：进残域打第 1 关 → 结算页正常出 4 颗奖励胶囊 →
自动下一关 5 秒倒计时接着开第 2、第 3 关；控制台每场都是 `battle · clear` +
`battle · end win=true`，**不再出现 `err=win is not defined`**，全程一条 `dun · resort` 都没有。
