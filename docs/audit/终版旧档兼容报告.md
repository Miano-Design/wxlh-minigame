# 《残域》终版旧档兼容报告

> 2026-10-03 · 终版升级任务书 §61-1
>
> 一句话结论：**老玩家更新之后，还是他那个存档，只是这个世界终于有故事了。**
> 不重打任何一关、不丢一颗星、不补发一分钱、也不被要求"重新体验一遍剧情"。

---

## 一、这次到底补了什么

剧情系统（B 批）是 2026-10-01 才加的。在那之前的版本里，玩家的玩法就是
「选世界 → 打关卡 → 推进下一世界」，存档里**天生没有 `S.story`**。

升级之后如果不做任何事，老玩家打开卷宗看到的是「剧情 0 / Boss 0 / 36」——
等于告诉他"你以前白玩了"，还有人会被要求"再打一遍才能看剧情"。

所以这一轮在 `Core.migrate()` 里加了一段**世界故事线自动补全**：

| 旧档里能拿到的证据 | 补出来的剧情 |
|---|---|
| `stages[任意难度]` 里有星（进过这张图） | `story.w[wid].in = 1` |
| 普通难度第 6 关已通 | 再加 `story.w[wid].mid = 1` |
| 普通难度 12/12 全通 / `worldFirstClear[wid_normal]` / `bestWorldIdx` 证明当年通关过 | 再加 `pre` + `post` + `story.b[wid]`（Boss 卷宗） |
| 已经拥有某位有故事的角色 | `story.c[charId].s1 = 1`（"首次获得"真的发生过） |

人物那一半写在 `js/sc-story.js` 的 `Story.migrateLegacyChars()` —— 名单在剧情数据里，
core 不该去读它；两半各自有自己的幂等标记。

## 二、判据为什么只能用"战斗进度"

任务书 §3.1 的原话是"数据判断必须基于历史进度，绝对不能基于现在剧情状态"。
落实下来有三条：

1. **不看 `S.story`**：它是空的**不代表没玩过**（那个年代根本没有这个字段）。
2. **不看 `worlds[wid].unlocked`**：开机 `refreshWorldUnlocks()` 会把 W01 解锁给一张
   刚建档的空档 —— 拿它当"进过"，新玩家一开局就会被标成"W01 已读过"（立尺子时当场抓到）。
3. **`bestWorldIdx` 的 `0` 有两种含义**（从没通关过 / 通关过 W01），所以沿用既有的
   两个护栏：`reincarnations >= 1` 或 `hi >= 1` 才算"当年通关过 W01"。

## 三、迁移写什么、不写什么

**只写** `story` 那四块（见上表），且**只把 0 写成 1**。

**一个字都不碰**：

* 关卡星数 —— 旧档里没有"当年三星还是两星"的任何留痕，写就是编数据（§29）；
* 任何资源 —— 这是历史资料补全，不是发奖；首通那笔账另有它的闸
  （`worldFirstClear` 在 V9.2 起就会把"已打穿的世界"标成已领过）；
* 世界解锁 —— 解锁只有一个真相 `refreshWorldUnlocks()`，剧情字段不参与战斗门禁（§8 / §45）。

## 四、幂等

标记 `storyLegacyMigrated` / `storyLegacyChars`：

* **只在第一次跑完时写**；
* **绝不写进 `defaultState()`** —— 写进去 `fillDefaults` 会先给老档补上它，
  这段就永远不进了（§5 / §58，本项目已经踩过好几次，`migration_fixture_audit` 最后一条在盯）；
* 函数本身也写成只增不减的数字，所以就算标记丢了、重跑一遍，结果**逐字相同**。

验证方式不是"看代码"，是**存盘再读一次，逐字段比快照**（任务书 §42 / §59）——
8 个夹具每一个都做了一遍，全部一致。

## 五、世界名改了，进度为什么不会丢

36 个世界在这一轮全换过身份（W05 无归客轮 → 迷雾林海、W12 蚀环远征 → 镜像城市 …）。

**存档里存的永远是 `W01~W36`，改的只是显示名。** 这条由三件事一起保证：

1. 代码里**没有任何一处**按世界名判进度（去注释后扫描，0 处）；
2. `D.WORLDS` 的 id 是连续的 `W01..W36`；
3. `docs/lore/旧名迁移表.md` 的"新名"与 `js/data.js` 逐字一致（文档与游戏不许各说各话）。

## 六、本轮顺手修掉的三个真问题

### 1. 最原始的档连 W01 都进不去（世界解锁）

`refreshWorldUnlocks()` 原来只在 `reincarnate` 与"转过生的老档补偿"两处被调 ——
一份 `S.worlds` 是空的老档读进来之后，连第一张图都是锁的。
现在把它补在**读档出口**（`migrate` 末尾）：开机 / 导入存档 / 切档 / 备份恢复四条路走完都过一遍。
判据仍是"上一世界普通 12/12"这个可证的事实，**不凭空开图**。

### 2. 地狱 Boss 掉本命装没走 W25 门（SIGNATURE 时代）

任务书 §35：**任何来源**产出 SIGNATURE 都必须过统一的 W25 gate。
查下来 UR 箱过了门，**地狱 Boss 那条没过** —— 而且地狱并不"很后期"：
打通 W01 普通 → W01 困难 → W01 地狱就能打，W25 以前照样刷，于是"W01 就掉本命装"。
已补上 `Core.inSignatureEra()`，并把这道门**导出**给其它来源用（判据只此一处）。

### 3. 云数据库坏了会被当成"你没有存档"（P0）

云库里 `doc(id).get()` **文档不存在时也会抛**，于是"这个玩家还没存过档"和
"数据库此刻是坏的"走进了同一个 catch —— 原来一律 `return null`，
客户端拿到就以为"云端没有存档"，接着**建一份新的**：数据库抖一下，
玩家一年的进度就被一份空档顶掉了。

现在云函数把三种结果分开：

| 情况 | 返回 | 客户端怎么办 |
|---|---|---|
| 读到了 | `ok:true, hasDoc:true` | 正常比时间戳 |
| 这个账号确实还没有云端存档 | `ok:true, hasDoc:false` | 该建就建（新玩家） |
| 读不出来（DB_ERROR） | `ok:false, code:'DB_ERROR'` | **绝不建新档**，给一句"云端暂时读不到，别删档"，稍后自动重试 |

老记录归并时 `where` 挂了也一样报 DB_ERROR（原来写的是 `list = []`，
等于"数据库一坏就判玩家是新账号"）。**判不出来一律当 DB_ERROR** ——
宁可让玩家多点一次重试，也绝不允许拿空档顶掉他的真实进度。

## 七、云同步的兼容口径（未改动，只是确认）

* 剧情进度就在 `S.story` 里、跟着整份存档走 —— **没有第二套剧情存储**；
* `S.worlds` / `S.story` / `S.player.bestWorldIdx` / `S.worldFirstClear` 属于**同一份档**，
  一起上传、一起下载，不会出现"战斗同步了、剧情没同步"；
* "谁新听谁的"判据仍是 `savedAt`（玩家真实产生进度时刷新）；
  自动心跳 / 离线结算**不刷新**它，不拿"现在时间"伪装成玩家产生了新进度。
