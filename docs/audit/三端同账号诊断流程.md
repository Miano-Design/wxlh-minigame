# 三端同账号存档 · 诊断流程（2026-10-03）

> 任务书 §10–§20。这份流程回答一个问题：**三台设备（开发者工具 / 真机调试 / 实体手机）
> 到底看的是不是同一份云存档？** 每一步都有可对照的字段，**不猜**。
> 禁止输出：openid 本体、存档全文。只看 hash 与时间戳。

## 一、先确认"是不是同一个微信账号"

在**三台**上各跑一次（开发者工具：console；真机：`GameGlobal.CloudSync.probe()`）：

```js
GameGlobal.CloudSync.probe()
```

把三份结果摊开，逐项比：

| 字段 | 含义 | 三台必须 |
|---|---|---|
| `local.accountFingerprint` | 服务端算的账号指纹（**不是 openid 本体**） | **完全一样** |
| `docId` | 确定性 `_id`＝`'CS'+sha1('wxlh|'+openid)` | **完全一样** |
| `version` | 云函数版本戳（`cloudfunctions/cloudsave/index.js` 的 `CLOUDSAVE_VERSION`） | **完全一样** |
| `env` | 云函数跑在哪套环境 | 一样 |
| `cloudTs` / `cloudHash` | 云端那份的时间戳与内容指纹 | 一样（或差一次同步） |
| `local.localSavedAt` / `localHash` | **本机**那份的时间戳与指纹 | 各台可以不同 |
| `local.deviceId` | 本机的设备号（只用来认租约） | 各台不同 |
| `leaseIsMine` | 本机当前有没有**写入权** | 只应有一台为 true |

**判据**：
- 三台的 `accountFingerprint` / `docId` 一样 ⇒ 是同一账号、同一条记录 —— 到此为止"账号不同"这条假设必须放弃；
- 三台 `version` 不一样 ⇒ **云函数没按当前源码部署**（GitHub 改了 ≠ 云端部署了）。
  去微信云开发控制台**重新上传部署 `cloudfunctions/cloudsave`**，再比一次。

## 二、再确认"谁的内容更新"（任务书 §14）

> **内容新旧只看 `save.savedAt`；`session / lease` 只代表"谁现在有写入权"。**

| 情形 | 判据 | 期望行为 |
|---|---|---|
| 云端更新 | `cloudTs > local.localSavedAt` | 自动拉云；**覆盖前**本机旧档进 `wxlh_save_v5_bak` |
| 本机更新 | `local.localSavedAt > cloudTs` | 本机取得写入权 → 推上云（覆盖前云端那份进 `prev*`） |
| 两边一样 | 两个 hash 相同 | 什么都不做（`skip:'clean'`） |

## 三、五个必测场景（任务书 §15）

| 场景 | 步骤 | 预期 |
|---|---|---|
| A | 手机打到 W02 → 退出；开发者工具启动 | 工具端**自动拉到 W02** |
| B | 工具端打到 W03 → 手机重开 | 手机**自动拉到 W03** |
| C | 手机本地比云新 | 手机取得写入权并上传 |
| D | 云端比本地新 | 自动拉云、本机旧档留 `_bak` |
| E | 两台同时开、只有一台真打 | 真打那台继续写；另一台只读（不会互相抢写） |

## 四、"开机自动同步"是怎么接的（任务书 §16）

`js/sc-cloud.js` 的 `boot()`：

- **开机 300ms** 就 `triggerAuto('boot')`（先让首帧落、再联网）；
- **切回前台**（`onShow`）立刻再拉一次；
- 第一次触摸**保留为兜底**（开机那次没跑成时补拉，同一次会话只拉一次）。

`boot()` 由 `game.js` 在首帧之后调用 —— 不需要玩家先点屏幕。

## 五、写入权的三条禁令（任务书 §13）

`js/sc-cloud.js` 的 `push()`：

- **错误 A（新进度被旧租约拦死）** → 已修：本机 `savedAt` 比云端新时，**先抢回租约再推一次**；
- **错误 C（只是开了下游戏就把另一台锁住）** → 已修：只有"云端那份不比本机旧"才转只读；
- **错误 B（旧设备的旧本地档覆盖新设备云端）** → 现行判据就是 §14 那条：
  推档前先比 `savedAt`，旧的一律不推（云端更新的分支先走 `applyCloudSave`）。

## 六、出事的排查顺序

```text
1. 三台各跑一次 probe → 比 accountFingerprint / docId
   不一样 → 账号或环境问题（很少见，先确认这一条）
2. 比 version / env
   不一样 → 重新部署 cloudsave 云函数（最常见）
3. 比 cloudTs / cloudHash 与各自 local.localSavedAt
   云端旧、本机新 → 本机该推（看 leaseIsMine）
   云端新、本机旧 → 本机该拉
4. 都不动 → 看设置页那行"云诊断"的 why/reason，或 LOG 里的
   `sync` / `sync_fail` / `push_ok` / `push_denied` / `take` 四种账
```
