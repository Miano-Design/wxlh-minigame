> 版本：NARRATIVE-UX-FINAL-2026-10 · 状态：**正式**
> 适用于：剧情台词、卷宗正文、系统提示、结算文案、按钮标签。

---

## 一、一句话风格

> **克制、冷静、短句、留白。**

读者的感受应该是"有人在旁边平静地记下了一件事"，不是"有个作者在给我讲这个故事"。

---

## 二、四种禁用腔

### ① 作者腔（渲染气氛）

```
✗ 这是一个非常神秘而又危险的地方……
✗ 你不知道接下来会发生什么……
✗ 可怕的怪物向你袭来……
```

**为什么禁**：这是作者在替玩家紧张。玩家不吃这一套，只会跳过。

### ② 解释腔（替玩家下结论）

```
✗ 他的内核：……
✗ 他留下的话：……
✗ 留下的谜团：……
✗ 原来，这一切都是因为……
```

**为什么禁**：玩家要自己得出那个结论。你写出来，他就少想一次。

### ③ 游戏腔（把系统话当剧情说）

```
✗ 点击下方的按钮继续
✗ 恭喜获得奖励！
✗ 任务完成度 3/5
```

界面上的话**在界面上说**；剧情里只说故事里的话。

### ④ 模板腔（换个名字就复用）

```
✗ 进入世界 → 发现这里有异常 → NPC 说一句话 → 战斗 → Boss 说一句话 → 获得卷宗 → 下一世界
```

36 个世界必须各有各的异常、机制、立场、调查方式、冲突、记录、战后变化、伏笔。
盯这条的是 `narrative_content_audit.js` 的 ②（36 条异常**不许重复**）。

## 三、正确写法长什么样

### 例：物件层（`k: 'o'`）

```
灯亮着。

没人点过它。

你看了一会儿。

灯芯突然短了一截。

旁边的卷宗写着：

【灯已熄灭】

你抬头。

它还亮着。
```

### 例：卷宗正文

```
封门那天量过：四十一步。今天走完五十三步。宽度没变。
```

### 例：Boss 的一句

```
你比记录里晚了六分钟。
```

**共同点**：只给事实；多出来的那半句是"不该存在的细节"，不是解释。

## 四、句法与排版

| 规则 | 说明 |
|---|---|
| 一拍一句 | 播放器一次只显一条核心信息；要拆成两句就拆成两拍 |
| 单拍 ≤ 220 字 | `audit_story` ⑨ 查的是这个（超了就是"这一段没法读"） |
| 单拍要装得下 | `audit_story` ⑬ 逐拍量高度，装不下当场红 |
| 说话人用**全称** | 台词里的人名 = 角色表 / Boss 表里的名字，逐字一致（`audit_story` ⑧-b）。不许简称 |
| 不写"他/她"指代 Boss | 玩家第一次读不知道"他"是谁 |

---

## 五、三种说话的层不许混

```
旁白（n）   世界自己在说话     —— 不用引号
对白（d）   角色 / Boss 在说话 —— 带全称说话人
物件（o）   关键物件 / 残响    —— 走高亮层，短
```

战斗里另有一条**系统层**（`【残域机制】…`）：它只说规则，不抒情，也不替 Boss 说话。

## 六、按钮与系统文案

### 可以继续用的（已经看得懂）

```
返回　关闭　取消　完成　继续　领取　确认　进入　查看
```

### 世界内可以更贴世界观的

```
进入世界   → 【点灯】
查看剧情   → 【继续记录】
查看卷宗   → 【翻阅卷宗】
重新挑战   → 【再入残域】
Boss 前准备 → 【确认执灯】
```

> ⚠️ **不许把所有按钮都改成玄学文案。**
> 判据只有一条：**玩家看一眼就知道点了会发生什么。**
> 看不懂的"氛围命名"是 bug，不是风格。

## 八、交稿前自问三句

1. **删掉形容词以后，这句话还剩信息吗？** 不剩就是空话。
2. **这句话是在讲故事，还是在讲设定？** 讲设定就删掉，让它留在卷宗里。
3. **玩家读完能不能多想到一件事？** 不能就重写。
