# 《残域》剧情 × 战斗融合（R1.6 叙事轮）

> 尺子：`scripts/story_battle_matrix.js`（本轮新增，已接进 `audit_release` 总闸）
> 跑法：`cd wxlh-minigame && node scripts/story_battle_matrix.js`

---

## 〇、这一轮改的是什么（一句话）

把 `剧情 → 突然进战斗 → 纯战斗 UI → 突然恢复剧情`，
接成 `发现 → 冲突 → **我亲手处理** → 世界变了 → 新线索`。

**没写一句新剧情**（§三十）：三处新增的文本全部取自已经存在的数据 ——
`BOSS[wid].say / inner / after`（Boss 表）、`Battle.MECHANICS[wid].note`（引擎里那行机制说明）。

## 一、新增的叙事层：`js/sc-story-battle.js`

一个模块，三件事，**没有任何一个 Boss 自己写监听**（§八 的硬要求）。

### ① Boss 出场序列（§三 / §四）：2.4 秒，只放一次

```
场景（战场已经画出来了，只是压暗 62%）
  ↓
Boss 立绘推上台（右 1/3，contain 不裁头；图没到就只演文字，绝不空框）
  ↓
三行字：Boss 名 → 它的台词（`say`）→ 它为什么挡在这里（`inner`）
  ↓
最上一行走**系统层**：【残域机制】本世界的规则（§二十四：系统 / 角色 分开）
  ↓
底部一条进度细线（让人知道"这是 2 秒过场，不是卡住"）
  ↓
战斗开始（`step()` 在出场期间**不推进任何一帧**）
```

- 时长 2.4 秒（§四 要求 2~5 秒），**不登记任何热区**（不挡撤离、不挡顶栏、不暂停游戏）。
- **只放一次**：用新增的 `S.story.e[worldId]`（BATTLE_SEEN）当闸门 ——
  失败重来也不放（§二十：同一件事不该看第四遍）。这一个键是**懒补**的，老档不用迁移。

### ② 战斗内残响：由**真实战斗事件**触发（§七 / §八）

`BattleStory.trigger(event)` 是唯一入口。所有事件都在战斗页的 `applyFrame` 里，
挂在**引擎真的发出那一帧**的地方：

| 事件 | 挂点（真帧） | 没有对应剧情句时 |
|---|---|---|
| `first_hit` | 第一次对 Boss 造成伤害 | 退 `BOSS.say` |
| `boss_hp75 / 50 / 25` | Boss 血量比跨过阈值 | — |
| `boss_phase_2 / 3` | 引擎的 `phase` 帧（70% / 30%） | — |
| `boss_skill` | `summon` 帧 | **系统层**：`【残域机制】` + 引擎的机制说明 |
| `boss_buff` | Boss 身上出现 `shield` | 同上 |
| `player_break` | Boss 身上出现负面 `status` | — |
| `boss_debuff` | 我方身上出现负面 `status` | — |
| `player_low_hp` | 我方任一单位掉到 30% 以下 | **系统层**：机制说明 |
| `world_rule` | `rule` 帧（世界规则改写） | **系统层**：机制说明 |
| `player_revive` | `revive` 帧 | — |

> **为什么会有"系统层"这一路**：36 个世界的 `mid` 各只有 **1 拍**（W36 两拍）——
> 现有内容就这么多，而 §三十 明写本轮不许重写剧情。
> 所以机制类事件走**系统层回声**：文本取引擎里那行 `note`（如「感染：敌人攻击附带中毒」），
> 带 `【残域机制】` 前缀、与角色台词在视觉上分开（§二十四）。
> 结果：每场 Boss 战至少 **1 条角色/旁白残响 + 若干条机制残响**，而且每一句都对应**真的发生过的事**。

残响的呈现完全沿用原来的那一行（战场上沿、1.8 秒自走、不登记热区、可叠加成队列依次播）。

### ③ 战后世界变化（§十三 / §十四 / §二十八）

守关 Boss **首通**那一次，结算层多一行：

```
（奖励胶囊）
战场变化
  你们的世界也在这条轨道上。编号已定。      ← BOSS[wid].after
发现：轨道图上亮起 36 个点。  [查看]        ← 已有的 `Story.clueOf`（线索）
（下一步按钮）
```

- 判据用**已有的** `firstClear`（不新造条件），只在第 12 关给；
- 重刷不打这一行（§二十）。

## 二、剧情状态（§二十一）：七档映射，只新增一个键

| 状态 | 存在哪 |
|---|---|
| UNSEEN | 下面全假 |
| INTRO_SEEN | `S.story.w[wid].in`（已有） |
| **BATTLE_SEEN** | **`S.story.e[wid]`（本轮唯一新增的键）** |
| BOSS_SEEN | `S.story.b[wid]`（已有） |
| EPILOGUE_SEEN | `S.story.w[wid].post`（已有） |
| CLUE_FOUND | 同上（线索就是 post 的关键物件） |
| CLEARED | `S.worlds[wid].stages.normal[11] > 0` |

`BattleStory.stageState(wid)` 会把这一组算出来（尺子与界面都读它）。

## 三、剧情 × 战斗矩阵（§三十一 / §三十二）

`story_battle_matrix.js` 逐世界输出五列，并跑 **11 项叙事完整度**。
数据全部来自**真数据 / 真引擎**：

- 战斗侧是**真跑**：`Dungeon.makeEnemies()` 生 Boss、`Battle.run()` 打完一场、
  看引擎到底给没给 `phase` 帧（不看代码里"写了就算"）；
- 残响侧读 `BattleStory.tableOf(wid)`（事件 → 句子的唯一映射）。

### 11 项结果（36 世界）

| 项 | 通过 |
|---|---|
| 为什么来到这里 | 36/36 |
| 这里发生什么 | 36/36 |
| 为什么必须战斗 | 36/36 |
| 敌人为什么阻止玩家 | 36/36 |
| 战斗机制是否来自世界设定 | **36/36**（世界描写 → `Battle.MECHANICS` 这条链是通的） |
| Boss 是否具有身份 | 36/36（六卷锚点要求 `inner`＋`say`，其余要求有名字） |
| Boss 战是否有阶段变化（真跑出来的帧） | **12/36**（原因见下） |
| 战斗中是否有至少一个叙事反馈 | 36/36 |
| 战斗胜利是否改变了什么 | 36/36 |
| 是否产生新线索 | 36/36 |
| 下一步是否自然 | 36/36 |

### 那个 12/36 是什么（**不是叙事层的锅**）

"阶段帧"只在 Boss 血量跨过 70% / 30% 时由引擎发出。探针按世界档次扫了 4 档队伍
（0.7× / 1.0× / 1.4× / 1.9×），**W13~W28 那一带跑不出来**：
要么队伍还没打到 70% 就被打死，要么一击把 Boss 秒了（`battle.js` 的阶段判定写在
`if (boss.hp > 0)` 里，死了就不再判）。

这与上一轮数值轮的结论**对得上**：W13~W20 是"要满配才过"的一段、
W21~W36 的 Boss 又是"43~100 回合的磨"。也就是说：
**这一段 Boss 的"阶段节点"对真实玩家很少可见** —— 它属数值轮，不是靠叙事层能修的。
本尺子把它如实报成 WARN，不粉饰。

## 四、没做的（说清楚）

| 项 | 为什么没做 |
|---|---|
| 给 36 个世界补更多残响台词（§七 的 75/50/25 各一句） | §三十 明写本轮不许重写剧情。**管线已经全通**（16 个事件都支持），下次内容轮只需往 `mid` 里加拍，代码一行不动 |
| 玩家行为参与叙事（§十九：常用某元素 → NPC 反应变化） | 需要新的存档维度 + 全 36 世界的分支文本，属独立一轮 |
| 失败时给机制线索（§二十三） | 结算层已经有"机制提示"的位置，但本轮没做文案设计，留给内容轮 |
| 战斗 UI 按世界微调（§二十六：W13 冰霜 / W25 镜面） | 属视觉层，需要真机看图调，交给下一轮 |
| 实机连续体验 W01→W03 与六个 Boss（§三十三） | **需要开发者工具**（模拟器截图 + 真机手感）。本轮的结论来自"真渲染 + 真跑战斗"的机器检查，**验收那一步我没做，不当通过** |
