## 三、两条**硬约束**（GPT 那份方案里没提，但会直接卡住上传）

### ① 包体：小游戏主包 4MB —— 10~14 张大背景**放不进主包**

现在加固后的上传件约 **3.5MB**。一张 1080×1920 的场景图就算压到 300KB，12 张也是 **+3.6MB** ⇒ **超限**。
所以第一期必须先定**一条**：

- **甲：分包**（把叙事素材放 `subpackage`，进剧情页时再下载）—— 首屏不变大，但要处理"首次进剧情要等等"；
- **乙：强压缩 + 限量**（每张压到 ~120KB、只用 8 张、分辨率降到 720×1280）—— 不折腾分包，但画面糙一点。

**这条不定，素材生成了也传不上去。**

### ② 项目自己的位图红线：**小尺寸一律不用位图**

`js/data.js` 里写死过一条（V1.1.2 那轮）："**绝不用生图当图标/头像**（位图小尺寸必糊、不可编辑、两端不同源）"。
所以对照 GPT 那份方案，分界线是：

- ✅ **允许位图**：剧情页的**大背景**、核心 Boss 的**大立绘**（大于 200px）；
- ❌ **继续程序化**：头像、图标、小徽记、剪影轮廓 —— 一律走现有 `D.avatarSpec / avatarParts` 与 `CV.GLYPHS`；
- ⚠️ 剪影可以**用代码画**（用现有头像部件放大 + 纯色填充），**不需要新素材**。

## 四、六层结构 ＋ 接入口（代码层，**不依赖素材就能先搭**）

```
背景层 background   母版图 + 裁切/镜像/缩放        ← 没图时先用程序生成的暗调渐变占位
氛围层 atmosphere   雾 / 雨 / 尘 / 粒子             ← 已有能力（CV 自绘，不需要素材）
光源层 light        光束 / 灯闪 / 呼吸              ← 已有能力
角色层 actor        剪影（代码画）/ 大立绘（位图）    ← 剪影先做，立绘后补
UI 层   frame       章节号 / 幕题 / 台词框 / 继续    ← 一套模板，全剧情复用
叙事层  story       台词 / 分支 / 触发条件           ← 数据驱动（`STORY` 表）
```

接入口（第一期只需要三个）：`CV.register('story', …)` 注册页；`Core.storyOf(worldId)` 取该世界该进度的段落；
`CV.push('story', { worldId, part })` 从世界页/首通/结算进入。
