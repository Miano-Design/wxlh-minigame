# 迁移方案（网页版 → 微信小游戏）

> 依据父亲大人 2026-09-16 转达的要求：**网页版是唯一标准，反向迁移，禁止自行设计/简化。**

## 0. 最高原则（红线）

1. 网页版是唯一标准：界面结构、页面顺序、功能、玩法、数值、按钮/弹窗/流程、存档逻辑，全部以它为准；
2. 小游戏只换**运行环境与渲染层**，不是重做一款游戏；
3. 禁止：删功能、简化玩法、合并页面、自造 UI、改配色/布局/字体层级、假数据/演示数据、
   改数值与概率、只做"能跑的 Demo"、因没有 DOM 就重写逻辑；
4. 暂时做不到的，**必须显式标记"待迁移"**，禁止静默删除；
5. 两边结果不一致时，**改小游戏，不改网页版**。

## 1. 架构（已落地）

```
网页版 js/{data,core,battle,dungeon}.js  ──逐字节同步──▶  小游戏 js/  ← 唯一规则来源
网页版 js/ui.js（界面层）                ──逐字节同步──▶  小游戏 js/ui-web.js
                                     │
                                      ▼  适配层（小游戏唯一手写）
        ce-dom.js（假 DOM：最小 DOM 树，让 ui.js 的绑定能生效）
        ce-html.js（HTML → 引擎标记；行内片段合并规则见文件注释）
        ce-context.js（上下文类名 / 行内样式→类名）
        ce-fit.js（按真实画布折算尺寸；含防死锁下限）
        ce-shell.js（顶栏/滚动区/底栏）· ce-engine.js（引擎管道）· ce-app.js（页签/点击派发）
        ce-style.js（由网页版 style.css 编译出的引擎样式表）
```

**证据**：`scripts/sync-logic.js` 每次跑都核对"网页版 4 份逻辑 + ui.js"逐字节一致（测试里有守卫用例）。

## 路线决定（2026-09-16，父亲大人拍板）

**改走 A：手写 canvas 界面（cv.js + screens.js），按网页版逐界面复刻到位。**

- 理由：父亲大人看两套后认为 **A 的观感更接近网页版**；
- A 的现状：35 个界面手绘坐标、配色**已照抄**网页版 `:root`（完全一致）、间距/圆角令牌也一致；
  但**布局是按 375 设计宽 + 整体缩放**（已改成按真实宽度排版）；
- 工作方式（每一页都必须过这三步）：
  1. 打开网页版同一页，逐项抄下：结构顺序、每块的**边距/内边距/字号/颜色/圆角**；
  2. 在 `screens.js` 里按同一套数值重画（用 `CV.W` 做相对计算，不许写死 375）；
  3. **手机/模拟器截图与网页版并排比**，差异项逐个修到一致；
- 清单以 `docs/WEB_FEATURE_INVENTORY.md` 为准（18 个页面 + 74 个面板/弹窗），**缺的功能要补上，不许略过**；
- B（引擎渲染）保留在工程里不删（`game.js` 的 `UI_ROUTE` 开关），随时可切回对比。
