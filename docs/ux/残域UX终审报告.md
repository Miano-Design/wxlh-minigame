## 三、我主动改善的 UX（已改，全部有尺子读数对照）

### 1. 设置页的"开关"不再画成金底主按钮

- **问题**：`背景音乐 / 音效 / 省电模式` 开着的时候是一颗**金底**的「已开启」——
  和「进入残域」「强化」长得一模一样。一屏出现 3 颗伪主按钮，页面第一动作看不出来（§三十二 / §三十三）。
- **改法**：新增 `switchRow()`（`js/sc-last.js`）——**轨道 + 状态圆点 + 状态字**，开＝金、关＝灰；
  颜色与文字两个通道同时表达状态。`toggle:*` 的动作 id 与逻辑一个字没动。
- **读数**：`ux_audit`「主按钮 >2 颗的页面」从 **4 页 → 1 页**。

### 2. 「已订阅」不再是金底

- 订阅那一行原来是 `已订阅 = primary`（金底）。**订阅成功是状态**，不是本页要玩家做的动作 → 降为描边。

### 3. 队伍「套用预设 1/2/3」三颗金底 → 描边

- 三颗同权重的按钮原来全是金底（一屏三颗主按钮）。预设是**工具**，不是这一页的第一动作。

### 4. 招募页「十连」降级

- 原来每张池卡**两颗都是金底**（免费抽 ＋ 十连），整页最多 5 颗金按钮。
- 口径：**免费/单抽 = 那张卡的主按钮**（不花钱的那一下），十连降成中性实底；
  **免费次数用完时**自动反过来（单抽变描边、十连变主按钮）——主次始终只有一个。

### 5. 新增 `scripts/ux_audit.js` 并接进发布总闸

- 真渲染 58 个页面，查：入口 / 出口 / 返回链 / 滚动三态 / 死按钮 / 热区碰撞 / 弹窗模态 /
  Toast / 空状态 / 锁定状态 / 文案（失败词、数字格式）/ 主按钮 / 按钮字数 / 四档屏宽出画 /
  底栏遮挡 / 连点 / 连返。
- ⚠️ 两条**口径写在尺子注释里**，防止下次又报假账：
  ① 底栏四格的处理器注册在**真实入口 `game.js`**，`js/` 里没有 —— 不补上会把 `tab:*` 误判成死按钮；
  ② `attr_card / party_board / stage_grid / hero:* / grid:*` 是**引导锚点**（整块、本来就没动作），
     白名单与测试台 `deadkey_audit` 逐条一致。

## 四、确认存在的问题 / 保持原样 / 未验证

### A. 确认存在的问题（**已修**）

见 §三 的 1~5。

### B. 检查后认为**没有问题、保持原样**（附理由）

| 现象 | 为什么不动 |
|---|---|
| 「整张卡可点 ＋ 卡里还有一颗同名按钮」（背包材料卡、招募结果返回、命格卡） | 刻意设计：整卡可点**正是**为了避免"手指一抖点到隔壁"（血统那次真实事故）；同名按钮是**视觉提示**，两者是同一个动作的两个入口，不是抢点 |
| `升级（◉ 1250）` 这类**带价格的按钮文案** >8 字 | 价格是点下去前**必须**知道的信息（§十一 的核心诉求）；把价格挪走会让玩家盲点 |
| 招募页 3 颗主按钮 | 是**三张池卡各一颗**（普通/高级/限定各有一个免费或十连主按钮），不是一页三颗互抢 |
| 名字里带"称号味"的伙伴（§十五 提到的那类） | 上一轮已按 §四十四 处理过（只改现实神话专名），本轮不重复改 |

### C. **未验证**（诚实记录，不当通过 —— §五十二 的 P0 判断需要它们）

| 项 | 为什么没验 | 建议怎么补 |
|---|---|---|
| 弹窗模态（开弹窗时下层不可点） | 静态渲染量不到，必须**点击后**才出现 | `wechatide automation_game_action` 实机点一次 |
| 切后台再回来（scroll / 按压态 / 拖拽态） | 需要真实 `onShow/onHide` | 模拟器切后台再回来 |
| 广告链路（剩余次数 → 点击 → 播放 → 奖励 → 扣次数 → UI 更新） | 需要真实广告位 | 真机/模拟器跑一遍 `ad_audit` 的场景 |
| 新素材与 UI 融合（世界页 / Boss 页 / 剧情页 / 首页 / 结算） | **要人眼** | 模拟器截图逐屏看（§十六 明写要真图，不是代码） |
| 图标尺寸与图标-文字基线（§三十五 / 三十六） | 本轮只做了 SVG 接入后的静态检查 | 需要逐图标量 `CV.AICO` 与基线 |
| 小屏下的**视觉密度**（不是"出画"，是"臃肿"） | 尺子只能量几何，量不了"看着挤" | 模拟器 320×568 截图人眼过 |
